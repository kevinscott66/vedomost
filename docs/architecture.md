# Архитектура и дизайн

FastAPI обслуживает JSON API и статические HTML/CSS/JS с одного origin. SQLite создаётся в lifespan приложения; запросы параметризованы, внешние ключи включены для каждого соединения. Запись выполняется в транзакции. Денежные расчёты проходят на сервере через Decimal и целые сотые доли. Клиент только отображает результаты API.

Таблицы: students(id, name, phone, group_name, monthly_fee_cents, start_month); payments(id, student_id, amount_cents, paid_on). Связь payments.student_id → students.id с ON DELETE RESTRICT. Индекс payments(student_id, paid_on). Список должников — LEFT JOIN платежей в полуоткрытом интервале [первое число месяца, первое число следующего месяца), GROUP BY ученику, HAVING сумма < тариф.

Веб-клиент использует нативные формы и dialog. Данные API вставляются через textContent, не через HTML. Устаревший ответ при смене месяца отбрасывается по номеру запроса. Загрузка не смешивается с отсутствием долга. Интерфейс не использует внешние шрифты, аналитику и CDN.

## Интерфейс и темы

Визуальный источник — выбранный пользователем тёмный макет Higgsfield / GPT Image2: [reference](../design/modern-dark.png), [prompt](../design/higgsfield-modern-dark.txt), [provenance](../design/provenance.json). Первоначальный светлый и бумажный варианты отклонены и в публичную версию не входят.

Графитовая рабочая область, мятные суммы и кнопка, компактная боковая навигация, таблица слева и форма справа на широком экране. Manrope размещён локально с латинским и кириллическим наборами; иконки Lucide также локальные. Никаких внешних шрифтов/CDN при запуске. Лицензии сторонних ресурсов — рядом с файлами и в THIRD_PARTY_NOTICES.md.

Светлая тема использует ту же композицию с белыми поверхностями и тёмно-зелёным акцентом. CSS-токены переключаются через html[data-theme]. Кнопка имеет доступное имя и сохраняет предпочтение темы в localStorage под ключом vedomost-theme. theme.js применяет сохранённый выбор до загрузки основного скрипта; запрет доступа к storage не мешает работе. По умолчанию тема тёмная. Данные учеников и платежей в браузерное хранилище не записываются.

На телефоне навигация становится верхней панелью, таблица — карточками, форма переносится ниже. Есть фокус, подписи форм, статусы отправки, состояния ошибок и reduced-motion. Кнопки предыдущего/следующего месяца меняют тот же фильтр /debtors. Смена темы не меняет данные, месяц и заполненную форму.

Для UI UX Pro Max использовались общие рекомендации по доступности и плотности данных на раннем этапе. Финальное визуальное направление взято из Higgsfield, а не из автоматически предложенного маркетингового шаблона.

## Языки и дополнительные страницы

Общий `translations.js` содержит RU, UZ (латиница) и EN; `i18n.js` обновляет подписи, доступные имена, сообщения, форматирование и заголовки. `theme.js` применяет сохранённые тему и язык до отрисовки. В localStorage лежат только предпочтения: `vedomost-theme`, `vedomost-language`, `vedomost-currency`. API-контракт, данные учеников и SQLite не локализуются. Месяцы имеют явные переводы, чтобы узбекские подписи не зависели от полноты CLDR браузера. Смена языка основной формы не удаляет введённые значения.

`/privacy`, `/terms`, `/rights` и `/docs` обслуживаются локально и используют общие CSS-токены, боковую навигацию, темы и язык. `document.js` создаёт DOM через textContent; юридический текст хранится в `legal-content.js`. Язык выбирает региональную редакцию уведомления (Россия / Узбекистан / пояснения EU/EEA и США), но сам по себе не определяет юрисдикцию. Это документация демонстрации без реального оператора учебного центра; недостающие сведения не выдуманы. Политика ссылается на первичные источники и описывает фактическое отсутствие cookies, аналитики, авторизации и автоматического удаления.

Встроенный Swagger с внешними ресурсами заменён локальным справочником и консолью фиксированных маршрутов. Консоль поддерживает методы API, JSON-тело, ID и месяц, показывает HTTP-статус и ответ. Записывающие запросы явно помечены как изменяющие локальную БД. `/openapi.json` сохраняется, `/redoc` перенаправляет на `/docs`. Тексты лицензии и сторонних уведомлений доступны по отдельным read-only маршрутам. Внешние ссылки не отправляют локальную базу.

## Валюта демонстрации

По просьбе пользователя суммы и поля ввода явно подписаны в узбекских сумах (UZS): сум / so‘m / UZS. Это выбранная единица демоверсии, поскольку задание не задаёт валюту. Базовая единица БД и ввода — UZS. Локализация не выбирает валюту; отдельный переключатель пересчитывает отображение в RUB/USD. Контракт API сохраняет десятичные строки UZS.

Демо-тарифы обновлены до500000–850000UZS в месяц, платежи согласованы с этим масштабом. Это правдоподобные вымышленные записи, не счета конкретного центра. Ориентиры, проверенные28октября2026: [Result School](https://result-school.uz/ru) публикует765000UZS за12уроков General English и810000UZS за12уроков CEFR; [Global School](https://www.globalschool.uz/) — математику от500000сум/месяц. Тариф информатики600000 — демонстрационное допущение, не цитата прайса. Локальные прежние фикстуры обновлены отдельно с резервной копией в игнорируемом data/. Автоматическая миграция чужих баз не добавлялась.

## Рефакторинг хранения и локальной границы

`app/database.py` — единый источник выбора пути, схемы и соединений для API и демо-CLI. Приоритет: явный путь, DATABASE_PATH, корневая data/school.sqlite3. Путь разрешается до запуска; вложение в app/static запрещено, включая разрешённые симлинки. `--database` у демо по умолчанию использует тот же выбор, что сервер.

Записывающие операции используют BEGIN IMMEDIATE до проверки существования/ссылок. WAL позволяет чтение во время записи; внешние ключи включены для всех соединений. Аддитивная миграция user_version1 создаёт payment_requests без изменения учеников/оплат. Ключ запроса связывается с нормализованными student_id/amount/date и payment_id в одной транзакции; дубли возвращают ту же запись, несовпадающее тело даёт409. Хранение ключей пока бессрочное вместе с историей. Клиенты без ключа сохраняют прежнюю семантику POST. Ошибка занятости БД возвращает503, другие ошибки не маскируются.

`app/security.py` — чистый ASGI middleware: явные loopback Host, точное сравнение Origin со схемой/Host/портом при записи, запрет cross-site записей, JSON Content-Type. Ответы получают CSP без inline/eval/внешних ресурсов, nosniff, no-referrer, no-store. Это защита локальной демонстрации от чужих веб-источников, не аутентификация и не поддержка публичного размещения. TLS/публичный прокси и реальные персональные данные остаются вне границ демо.

## Валютное отображение

`currency.js` хранит в localStorage только выбранный код и пересчитывает отображение из UZS. Форма/API/SQLite остаются в UZS. `/exchange-rates` возвращает ставки UZS за одну единицу RUB/USD, источник CBU/CBR/reference, дату действия, UTC-время получения и состояние fresh/stale/fallback. В браузере нет прямых запросов к внешним сайтам; CSP остаётся same-origin.

`app/exchange_rates.py` использует фиксированные HTTPS-адреса ЦБ Узбекистана и резервного Банка России. Оба запроса привязаны к текущей московской календарной дате: запрос CBU без даты может вернуть старую подборку, а CBR без даты — курс на завтра. CBU нормализует Rate/Nominal; резервный CBR даёт UZS/RUB из Nominal/Value для UZS и UZS/USD через котировку USD/RUB. Разные источники явно различаются в UI. Это справочные дневные ставки; более ранняя дата в праздничный день допустима, но дата не скрывается.

Сервис создаётся на экземпляр приложения, без сетевого запроса при запуске. При обращении он синхронизирует обновление блокировкой, использует часовой кеш и пятиминутный интервал повторов при сбоях. Последняя успешная загрузка атомарно сохраняется в `<имя-файла-БД>.exchange-rates.json` рядом с файлом БД. При отказе сети используются прежние данные со статусом stale; начальный резерв reference имеет дату 28.10.2026 и не выдаётся за свежую загрузку. Таймауты, предел размера ответа, проверка чисел/дат и ограниченные перенаправления применяются к внешним данным. Схема SQLite не меняется.

Браузер запрашивает тот же origin при старте, раз в 15 минут на видимой вкладке, при online и возврате видимости; одновременные запросы объединяются. Новые ставки вызывают currencychange и перерисовку сумм, сохраняя введённые значения. Источник, дата действия, время получения и состояние переводятся в RU/UZ/EN. Поставщики курса видят IP сервера и HTTP-запрос, но не записи ведомости. Из-за округления сумма видимых строк может на сотую отличаться от пересчитанного итога.

## Начало обучения и исторические отчёты

По уточнению пользователя прошлые даты сохранены, но долг до начала обучения не создаётся. `start_month` — YYYY-MM в карточке ученика, по умолчанию текущий месяц сервера при создании. В PUT отсутствие поля сохраняет прежнее значение. Отчёт фильтрует учеников start_month<=выбранный месяц; до начала всех учеников UI показывает «Начислений ещё нет», а не «Всё оплачено». Оплаты раньше start_month отклоняются422; перенос начала позже существующей оплаты —409. Это месяц начисления полного тарифа, без пропорционального расчёта и истории тарифов.

Аддитивная транзакционная миграция user_version2 добавляет start_month. У старых записей без известной даты используется минимум текущего месяца и месяца самой ранней оплаты. Это консервативная начальная оценка, которую владелец уточняет в карточке, а не утверждение о реальной дате зачисления. Ученики, суммы, даты и ключи оплат не переписываются. Демогенератор записывает текущий месяц явно.

Строка «Внести» привязывает форму к месяцу отчёта. Если прежняя дата из другого месяца, она очищается; пользователь выбирает фактический день внутри месяца, видит пояснение. Изменение ученика снимает привязку и оставляет общий предел «не раньше начала обучения». Поддержан полный диапазон0001-01…9999-12; декабрь9999 использует открытый верхний пределSQL. ID входных/маршрутных параметров ограничены положительным signed64 до связывания сSQLite, чтобы огромные значения возвращали422 вместо500.


## Асинхронные состояния интерфейса

Подготовка формы через «Внести» и открытие редактора очищают только customValidity; обязательность, суммы и календарные ограничения продолжает проверять браузер. Смена ученика пересчитывает границы даты и снимает устаревшую пользовательскую ошибку. События input/change сбрасывают переведённую ошибку валидации.

Во время оплаты поля и кнопки строк недоступны; обработчик дополнительно проверяет paymentPending, в том числе после смены языка/валюты. Редактор блокирует исходные поля на время записи. Новая открытая форма получает собственную ревизию: старый ответ не закрывает её и не выводит в ней чужую ошибку. У удаления тот же принцип, отдельная блокировка повторного запроса и захваченный ID. Успешная операция обновляет списки, сохраняя более новый черновик.

Каждый запрос отчёта сразу очищает предыдущие суммы и действия, показывая загрузку. lastReport существует только для полученного текущего ответа; переключение языка/валюты сохраняет загрузку или ошибку вместо восстановления прошлого месяца. generation по-прежнему отбрасывает запоздавшие ответы. Схема БД в этой итерации не менялась.
